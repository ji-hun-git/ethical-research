# Korean academic register

This file tells Ethical Research **how to write Korean that reads like real scholarship**,
not like English run through a translator. When producing Korean academic output,
follow these conventions.

The guiding principle: **compose in Korean from the start.** Do not draft in
English and translate. Translated academic Korean has a recognizable, awkward
texture (subject pronouns everywhere, English connective logic, mistranslated
terms). Native composition avoids it.

---

## 1. Sentence-final style (문체)

Academic Korean prose uses **문어체 평서형** — the plain declarative, not the
polite spoken `-습니다/-해요` forms.

- Verbs end in `-ㄴ다 / -는다`: 분석한다, 살펴본다, 제시한다.
- Adjectives and copula end in `-다 / -이다`: 중요하다, 분명하다, 한계이다.
- **Do not** use `-습니다 / -합니다` in the body of a paper, abstract, or
  literature review. (That register belongs to presentations, defenses, emails,
  and this README — not the manuscript.)

> Spoken/translated feel: "이 연구는 ~를 분석합니다."
> Academic: "이 연구는 ~를 분석한다."

## 2. Drop unnecessary subjects

Korean is a pro-drop language. English-driven drafts over-specify subjects
("그것은", "이것은", "그들은"). Remove them when context makes the subject clear.

> Awkward: "그것은 중요한 결과이다. 그것은 선행연구와 일치한다."
> Natural: "이는 중요한 결과이며, 선행연구와 일치한다."

Prefer `이/그/본` + noun (본 연구, 이 결과, 해당 표본) over bare pronouns.

## 3. Hedging and stance (완곡·태도 표현)

Academic claims are calibrated, not absolute. Use Korean hedges that match the
strength of the evidence:

| Strength | Korean | Rough English |
|---|---|---|
| Strong | ~을 보여준다, ~임을 확인하였다 | shows, confirmed |
| Moderate | ~을 시사한다, ~으로 나타났다 | suggests, was found to |
| Tentative | ~로 보인다, ~일 가능성이 있다, ~로 추정된다 | appears to, may, is presumed |
| Limiting | ~에 그친다, ~에는 한계가 있다 | is limited to, has limitations |

Match the hedge to the evidence Ethical Research actually has. Never upgrade a tentative
finding to a strong one for fluency's sake — that is the register equivalent of
fabrication.

## 4. Connectives of argument (논증 연결어)

Use written-register connectives, not conversational ones (그래서, 근데, 그러니까).

| Function | Use | Avoid (spoken) |
|---|---|---|
| Contrast | 그러나, 한편, 반면 | 근데, 하지만(weaker) |
| Cause/result | 따라서, 그러므로, 이에 따라 | 그래서 |
| Addition | 또한, 아울러, 나아가 | 그리고(overused) |
| Reformulation | 즉, 다시 말해 | 그러니까 |
| Example | 예컨대, 가령 | 예를 들면(ok but plainer) |
| Basis | ~에 근거하여, ~을 토대로 | — |

## 5. Nominalization and density

Academic Korean favors noun-phrase density and `-음/-기` nominalization and
Sino-Korean compounds: 검토(review), 분석(analysis), 도출(derivation),
규명(elucidation), 함의(implication). Prefer 수행하다/실시하다 over plain 하다 for
methods ("설문을 실시하였다", "분석을 수행하였다").

## 6. Standard section names (IMRaD → 국문)

| English | Korean |
|---|---|
| Introduction | 서론 |
| Literature review / Background | 이론적 배경 / 선행연구 검토 |
| Methods | 연구방법 |
| Results | 연구결과 |
| Discussion | 논의 |
| Conclusion | 결론 |
| Limitations | 연구의 한계 |
| Implications | 시사점 |
| References | 참고문헌 |

## 7. Citations and proper nouns — never translate

- Author names, journal titles, and DOIs stay in their original script.
- In-text Korean citation style commonly uses `저자(연도)` — e.g. "김민수(2023)는
  ~라고 주장한다." For Western authors: "Smith(2021)는 ~을 보고하였다."
- A translated quotation must be flagged: "(필자 번역)" or "[번역]". Never present
  a translated quote as if it were the original wording.
- Mixed-script terms: give the Korean term with the English in parentheses on
  first use — "생성형 인공지능(generative AI)" — then use the Korean alone.

## 8. Common L1-interference errors to avoid

- **Over-literal connectives** copied from English ("그리고" for every "and").
- **Tense leakage**: Korean often uses `-었-` for completed research acts
  ("분석하였다", "조사하였다"), present `-ㄴ다` for general statements/claims.
- **Article ghosts**: no "a/the"; don't insert 하나의/그 to mimic them.
- **Comma splicing** English-style; Korean prefers connective endings
  (-며, -고, -으나) to join clauses.
- **Passive overuse**: Korean tolerates fewer `-되다/-어지다` passives than
  English; prefer active where natural ("선행연구는 ~을 보고한다").

---

When the user asks for **side-by-side bilingual** output, compose each language
independently to these standards and the English equivalent — do not produce one
as a translation of the other. The two should *say the same thing*, each in its
own native academic voice.
